# Ren'Py 调试速查

内容来自工作台 host 桥接实现 + demo 项目实测（warp 格式、运行命令、窗口/截图坑）。

## 0. 画面验证纪律（最重要）

- **默认不自己检查调试画面**：除非用户明确要求（或你主动询问并获同意），**不要**自己去截屏后做像素分析/颜色统计来验证画面对不对。
- **优先让用户看**：让用户自己看游戏画面/截图并反馈（`renpy_screenshot` 给用户看，或让用户描述看到什么）。
- **多模态可用时**：若当前模型支持图片输入（部分模型可 `read_image`），且用户要求你检查画面，可用截图 + 读图验证；仍以用户反馈为准。
- **为什么**：像素级"自检"成本高、易误判（窗口坐标/取色偏差），且常与用户看到的不一致；用户的反馈又快又准。

## 1. 运行 / 停止 / 状态

| 操作 | 命令 | 说明 |
|---|---|---|
| 启动 | `renpy_run <项目>` | 等价 `python renpy.py <项目> run`；自动先停旧实例；注入调试桥接 |
| 停止 | `renpy_stop <项目>` | 停正在运行的实例 |
| 状态 | `renpy_status <项目>` | 运行中/退出码 + 最近输出 |

- 底层命令（手动执行时）：`<sdk>/lib/py3-windows-x86_64/python.exe <sdk>/renpy.py <项目路径> run`
- **别盲目重跑**：`renpy_run` 后不确定就用 `renpy_status` 看，不要连续重复 run（每次 run 会先杀旧进程，反复跑会丢现场）。

## 2. --warp 跳转（定位到某处）

- **格式是 `文件名:行号`，不是 label 名**！例：`--warp game/script.rpy:12`。
- 传 label 名会报 `No : found in warp location.`
- 工作台里更简单：**路线图面板点节点**（route-jump 已封装正确格式）。
- 用法场景：游戏启动后直接跳到某 label/场景验证，跳过前面流程。

## 3. 截图与画面验证

| 方式 | 适用 |
|---|---|
| `renpy_screenshot` | 整屏截图保存 PNG，**给用户看 / 让用户确认** |
| 工作台 🎬 实时画面面板 | 游戏内截图 + 点击/推进/回滚操作 |
| `read_image` 读图 | **仅当**模型支持图片输入**且**用户要求你检查画面时 |
| 像素分析脚本（最后手段） | 用户明确要求自动化验证时；注意窗口坐标/取色偏差 |

- 截图默认在 `userDir/screenshots/`（工作台）或游戏内 `game/_shot.png`（桥接）。
- **视觉问题（布局/颜色/文字）一律先问用户**：用户看到的即事实。

## 4. 调试桥接（工作台内置）

运行游戏时自动注入 `_debug_bridge.rpy`：

| 面板 | 能力 |
|---|---|
| 🗺 路线图 | label 状态机图；点击节点 → 游戏跳转（等价 warp）；轮询当前进度 |
| 🎬 实时画面 | 游戏内截图 + 点击模拟/推进/回滚（桥接指令） |
| 📊 运行时变量 | 变量快照轮询，变化高亮 |
| 🐞 报错诊断 | 读 `traceback.txt`/`log.txt`/`errors.txt` 结构化显示 + 根因定位 |

崩溃后看 **traceback.txt**：`-- Full Traceback` 分隔，根因 = 最深 `game/` 帧。

## 5. 常见坑（实测踩过）

- **warp 格式**：`filename:line`；别传 label 名（见 §2）。
- **手写 PowerShell 找窗口**：`FindWindow` 精确标题常失败（标题变化）；`LP` 是 `Out-Printer` 别名（函数名别叫 LP）；`$a, $b-1` 逗号与减号优先级要加括号；嵌套 `pwsh` 可能不在 PATH（用 `powershell.exe` 或直接走工作台接口）。
- **模型不能读图时的自检**：别用像素分析硬验画面（见 §0 纪律），让用户看。
- **调试残留**：崩溃/调试后清 `log.txt`、`traceback.txt`、`game/*.rpyc`、`game/cache/` 再打包交付。
- **运行环境**：确保用 SDK 自带 python（`py3-windows-x86_64/python.exe`），不要依赖系统 PATH 的 python。

## 6. 典型调试流程

1. `renpy_lint` 先过语法（有错先修）。
2. `renpy_run` 启动；`renpy_status` 确认进程在跑。
3. 需要定位：路线图点节点 或 `--warp game/script.rpy:<行号>`。
4. 画面/流程验证：**让用户看**（截图给用户 / 问用户看到什么）；用户要求 AI 看且模型支持读图时用截图 + `read_image`。
5. 崩溃：看 🐞 报错诊断（traceback 根因）→ 修 → 重跑。
6. 完成后 `renpy_stop`，清理调试残留。
